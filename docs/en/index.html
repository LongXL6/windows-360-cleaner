See the evidence before deciding what to remove

Windows 360 Cleaner supports rule-guided agent help and a no-agent, double-click route. It scans locally, separates evidence-backed 360/Qihoo targets from findings that still need judgment, and acts only after you review and explicitly approve exact targets.

Your first run

Follow all four steps and review the report

  1. 1

    Download and extract

    Download the ZIP from the official GitHub repository and extract the complete folder. Avoid modified copies from third-party download sites.

  2. 2

    Run Scan first

    Double-click scripts\Scan-360.cmd. Scan is read-only, does not require administrator access, and does not delete files.

  3. 3

    Review the JSON report

    Inspect each path, evidence note, and classification. A filename containing “360” is not removal evidence by itself.

  4. 4

    Approve before Remove; restart before Verify

    Remove handles only approved targets that are still confirmed. Removal is permanent. Restart Windows afterward, then run Verify to check for remaining Confirmed findings.

Read the scan correctly

Two labels define two different action boundaries

Classification comes from local paths, product records, tasks, services, signatures, or file evidence. It is not a broad name match.

Confirmed
The evidence meets the project's rules. It is still not removed automatically; you must review and explicitly approve the exact target.
ReviewOnly
The evidence is incomplete, ambiguous, driver-related, or from an offline Windows installation. The project reports it but does not remove it automatically.

Preserved by default

Normal files and personal data are not targets because of a name

Ordinary numeric files

Photos, game assets, models, hashes, and other content whose only signal is “360” in a name are not product evidence.

Windows and drivers

Built-in screen savers, GPU and network drivers, Driver Genius, and unrelated applications are not broadly removed by keyword.

Browser profiles

Bookmarks, history, and sessions stay by default. Profile removal needs a backup, a separate scan option, and explicit approval.

Other Windows installations

A Windows installation on another mounted drive is scan-and-report only. This project provides no cross-system removal mode.

Privacy and reports

Results stay local; inspect reports before sharing

This introduction contains no analytics, advertising, or tracking scripts. Scan, Remove, and Verify run in local PowerShell and write results to a local JSON report.

The computer and user fields are blank by default, but approval context, user SIDs, and finding paths can still expose identity. Keep the original local Scan report unchanged for Remove; create a separate redacted copy for public help, and never use that edited copy for Remove.

Frequently asked questions

What to know before you begin

Is this a one-click cleaner?

No. It is an AI agent skill package with double-click fallback scripts. The workflow always starts with a scan and human review before any removal decision.

What software or problems can it check?

Current rules cover evidence-backed 360 Security Guard, 360 Browser uninstall leftovers, 360 Huabao/Duohui screen savers, and related updater tasks. They do not cover every version or variant; see the detection catalog for the maintained scope.

Does Scan remove target software?

No. Scan does not require administrator access and does not remove target software. It creates a new local JSON report for review.

What should I do with ReviewOnly?

Do not force-delete it. Keep the target, inspect its signature, version, and path, then open a GitHub Issue with redacted evidence if it remains unclear.

Does a successful Remove prove everything is gone?

Not by itself. The Remove action report and the post-restart Verify report are separate evidence stages. Check Verify for remaining Confirmed findings.

Do I need an AI agent?

No. Download the ZIP and follow the beginner guide to run Scan, review the report, and decide whether to continue with Remove and Verify.
