# 第一次使用 Windows 360 Cleaner

[返回首页](../README.md) · [English](getting-started.en.md)

想检查 360 软件、画报或多绘屏保的残留，可以先用本工具生成一份扫描报告。**第一轮只扫描、读报告，到这里就可以停。** 清理功能需要另行批准。

适用环境：Windows 10/11、系统自带 Windows PowerShell 5.1 或更高版本。手机可以阅读本指南；脚本需要在要检查的 Windows 电脑上运行。普通聊天机器人未必能控制你的电脑。

## 1. 下载并完整解压

1. 打开 [项目主页](https://github.com/LongXL6/windows-360-cleaner)，确认所有者为 `LongXL6`、仓库名为 `windows-360-cleaner`。
2. 点击 **Code → Download ZIP**，也可 [直接下载 main 分支 ZIP](https://github.com/LongXL6/windows-360-cleaner/archive/refs/heads/main.zip)。下载和阅读公开仓库不需要 GitHub 账号。
3. 在文件资源管理器中右键 ZIP，选择 **全部解压**。打开解压后的文件夹，确认能同时看到 `SKILL.md`、`scripts` 和 `references`。
4. 进入 `scripts`，确认 `Scan-360.cmd` 与 `Invoke-360Cleanup.ps1` 在同一文件夹。不要只保存一个 `.cmd` 文件，也不要在压缩包预览里直接运行。

这是脚本包，不需要寻找 `.exe` 安装程序。下载 ZIP 本身不会开始扫描或删除。

## 2. 双击 Scan，只读扫描

双击 `scripts\Scan-360.cmd`。窗口会显示 `Windows 360 Cleaner - Scan`，列出结果，然后显示 `Report:` 和一个 `.json` 文件路径。扫描读取本机状态并新建报告，不删除目标软件，不需要管理员授权。

报告默认写入 Windows 的桌面目录，文件名类似 `360-cleanup-report-日期时间-随机标记.json`。如果系统未返回桌面路径，会使用临时目录；桌面受 OneDrive 重定向时也可能与预期位置不同。**以窗口实际显示的 `Report:` 路径为准**，不要只在下载目录寻找。

窗口最后会等待你按键。先记下报告位置，再关闭窗口。出现错误且没有成功写出的报告时，本次扫描尚未完成。

## 3. 看懂报告，决定是否继续

可以用记事本打开 JSON，或让能够访问本机文件的 Agent 解释。JSON 是记录结果的文本文件，不是让你双击执行的程序。

| 看到的内容 | 含义 | 现在做什么 |
|---|---|---|
| `Confirmed` | 当前检测规则找到了匹配证据 | 逐项看 `Name`、`Target`、`Reason`，确认自己是否真的要移除 |
| `ReviewOnly` | 仅供复核，可能是证据不足、受保护资料或离线系统对象 | 默认不删除；不确定时求助 |
| `No matching 360/Qihoo findings.` | 这次扫描没有命中现有规则 | 可以结束；不代表全系统不存在任何问题 |
| 拒绝访问、错误或检查不完整 | 部分状态没有成功读取 | 保存错误信息，先求助，不追加强制删除参数 |

报告里的 `Confirmed` 是证据等级，**不是你已经同意删除**。先检查整份报告；浏览器书签、历史和会话资料默认保留。正常照片、游戏或文件夹仅因名字含 `360` 不会被认定为目标。

给 Agent 的简短提示词：

```text
请先读取项目的 SKILL.md，只解释这份 Scan 报告，不执行删除。
把 Confirmed、ReviewOnly 和默认保留项分开说明，解释每个拟删除目标和风险。
如果这是脱敏节选，请说明无法据此确认完整扫描结果，等我审阅原始报告后再决定。
```

### 报告怎样分享才合适？

默认不填 `ComputerName` / `User` 字段，**不等于完全匿名**。路径、用户 SID、批准上下文、任务参数和软件名称仍可能暴露个人信息。

- 原始 Scan JSON 留在本机，不编辑、不公开上传；它是后续 Remove 使用的批准清单。
- 另做分享副本或相关条目的节选，遮盖用户名、私人路径、SID、无关任务参数等。标明“脱敏节选”，避免别人把它当作全量结果。
- 脱敏副本只用来讨论，不能拿来执行 Remove。不要为了选几个目标而手改原始报告；当前双击流程按整份报告中获批且仍然 Confirmed 的目标执行，没有逐项勾选界面。
- 使用云端 Agent 前先确认愿意上传哪些信息；也可以只阅读本地报告、不上传。

## 4. 确定要清理时，再执行 Remove

先备份需要的文件和浏览器资料。若 Windows“已安装的应用”中有正常可用的卸载入口，可先使用厂商卸载，再重新 Scan 检查残留。

下面的操作会永久删除，不进入回收站。只在你已经看懂并批准原始 Scan 报告中的全部拟处理目标后继续；有任何不想删除的项目就先停下。

1. 关闭目标软件和相关浏览器。
2. 双击 `scripts\Remove-360.cmd`。
3. 阅读警告；确定继续时按 `Y`，然后输入窗口要求的 **`REMOVE-360`**。
4. 将**同一份已审阅、未改动的原始 Scan JSON** 拖入窗口，按回车。不要使用 Verify 报告或脱敏副本。
5. Windows 请求管理员授权时，确认这是刚才的操作，再决定是否允许。没有管理员权限时，请联系电脑管理员。
6. 回到原窗口查看动作与 `Removal summary`，保存新的报告。新增但未获批的目标不会自动删除；跳过、失败和待处理项仍需要后续判断。

如果不想继续，在初次 `Continue? [Y/N]` 提示按 `N` 取消。不要复制高级 PowerShell 示例里的确认短语到这里：双击入口要求的是 `REMOVE-360`。

## 5. 重启并 Verify

保存正在处理的工作，重启 Windows 一次，再双击 `scripts\Verify-360.cmd`。它会只读复检并新建另一份 JSON；通过报告的 `Mode` 字段区分 `Scan`、`Remove`、`Verify`。

- 出现 `Verification passed`：本轮 Verify 的 `Confirmed` 数为 0；仍需查看可能存在的 `ReviewOnly`，也不保证将来不再出现。
- 出现 `confirmed finding(s) remain`：仍有检测到的目标。提供脱敏的剩余条目求助，或重新 Scan、重新审阅，不能直接沿用旧批准继续扩大删除。
- Remove 的 `ImmediateRescanComplete` 为 `false`：即时剩余状态未知，不能把旧 Findings 解释为已清理后的状态。

文件“逻辑大小”不等于实际释放磁盘空间。完整统计口径见 [首页](../README.md#清理结束会得到什么) 与 [SKILL.md](../SKILL.md)。

## 常见卡点

| 问题 | 下一步 |
|---|---|
| 手机打不开脚本，或使用 macOS/Linux | 把完整 ZIP 下载到要检查的 Windows 电脑上；其他系统不能执行这个 Windows 清理流程 |
| 双击没反应、窗口报错或找不到 `.ps1` | 确认已经全部解压且文件齐全；重新打开 Scan，记录错误，不改注册表或系统策略 |
| Windows 或组织策略阻止运行 | 核对来源与文件，保留提示并咨询管理员；不要关闭安全防护或全局放宽策略 |
| 报告不在桌面、桌面不可写 | 按窗口 `Report:` 路径查找；如是写入错误，提供错误文字求助 |
| Agent 说“完成”，但没有命令结果或报告 | 要求它说明是否有本机终端权限；没有时自己运行 Scan，别把建议当执行结果 |
| 360 或多绘屏保又出现 | 重新 Scan，查看更新服务、计划任务和来源证据，参考 [疑难排查](troubleshooting.md) |

仍需帮助时，[打开求助 Issue](https://github.com/LongXL6/windows-360-cleaner/issues/new?template=help.yml)（需登录 GitHub）。填写 Windows 版本、卡在哪一步、预期结果与脱敏错误即可；不要直接附整份原始报告。也可使用 [首页的作者联系渠道](../README.md#联系作者)。
